# 复盘闭环与算法异常应对

## 数据采集（推特晚班/复盘时）

computer-use 读用户 Chrome 的 x.com/vill1y 主页：
- 每帖的 浏览/回复/转帖/喜欢（从发布日志反查当日帖子）
- 关注者总数（当日增量记入复盘文件）
页面读不到时用截图兜底；两项都拿不到则只复盘回复执行情况并说明。

## 归因标签（每帖 4 个维度）

结构类型（六类之一）｜素材层（L1–L4）｜发布时段｜首句钩子（判断式/悬念式/数字式/场景式）

## 权重调整规则（复盘时执行）

- 某结构/素材层近 3 天平均浏览 > 全体均值 ×2 → 次日配比 +1（从垫底类挪）
- 近 3 天平均浏览 < 全体均值 ×0.5 → 次日配比 −1；连续 5 天垫底 → 该组合进黑名单
- 黑名单记：话题 × 句式 × 钩子的组合，30 天后可复议
- 整体代理指标：当日新增关注者数（回复的引流效果无法按帖归因，用整体数观察）

## 算法异常应对（「推特诊断」触发条件）

近 3 天总浏览 < 基线（近 14 天日均）×50%，或连续 5 帖展示 <100：

1. 先自查行为面：是否频率异常、句式重复、被折叠（贴长链接过多）
2. WebSearch / dbs-standard-answer 调研：X 算法近期公开变化 + 中文 AI 圈近 7 天爆帖的共性（入口、结构、情绪）
3. 产出：问题定位 → 新规则草案 → 经用户确认后更新 review-loop.md 与 content-system.md
4. 调研期间不擅自改变发布频率

## 复盘文件格式

`复盘/YYYY-MM-DD.md`：当日各帖数据表 → 赢家/输家各 2 条及原因 → 次日配比变化 → 黑名单增删。
